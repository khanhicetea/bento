## Connect a repository

```bash
bento app git shop --repo git@github.com:owner/repo.git --branch main   # prints the deploy key to register
bento app deploy shop
```

Private repositories use SSH with a per-app ed25519 deploy key generated by Bento; add the public key to the repository
as a read-only deploy key. HTTPS URLs are for public repositories only.

A deploy clones into an empty `app/` or resets tracked files to the branch head (untracked files such as `.env` and
`vendor/` are kept), then reloads the app process if it is running.

## `~/deploy.sh`

If `/home/<slug>/deploy.sh` exists, every deploy (manual or webhook) runs it after the fetch and before the reload:

- as the app user, from `/home/<slug>/app`, with the app environment (database bindings included);
- it must be a regular executable file owned by the app, with a shebang (`#!/bin/sh`); anything else fails the deploy
  before it starts;
- output appears in the operation events; the time limit is 15 minutes;
- if it fails, the new code stays checked out but the app is **not** reloaded and the deploy is not recorded.

It receives:

| Variable | Value |
| --- | --- |
| `BENTO_DEPLOY_TRIGGER` | `manual` or `webhook` |
| `BENTO_COMMIT` / `BENTO_PREVIOUS_COMMIT` | checked-out commit / last successfully deployed commit (empty on first deploy) |
| `BENTO_BRANCH`, `BENTO_REPO_URL`, `BENTO_OPERATION_ID` | the configured source and the operation |
| `BENTO_WEBHOOK_PROVIDER`, `_EVENT`, `_DELIVERY`, `_REF`, `_COMMIT`, `_PUSHER` | webhook deploys only, as reported by the git host |

Ready-made scripts for PHP apps (in-place and release-directory layouts) are in
[Deploy script recipes](/guides/apps/deploy-scripts/). To deploy on every push, see
[Auto deploy](/guides/apps/auto-deploy/).
