## Database servers

A stack runs shared database servers — MySQL (8.0, 8.4, 9.7) and PostgreSQL (14–18). Each app gets its **own user
and databases** on them; apps can't see each other's data. Only apps bound to one of them join the private data
network.

## Bindings

A **binding** connects an app to a server. Adding one creates:

- a database user just for this app,
- a database named `<slug>_main` (add more, like `shop_reports`, any time).

Bindings are **add-only**: Bento never drops a database or changes a password behind your back. You can also bind
**SQLite** — a private folder for a `.db` file.

## Credentials are injected

You never copy passwords around. The app gets environment variables:

| Variables | For |
| --- | --- |
| `DB_CONNECTION`, `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` | the first binding (Laravel-ready) |
| `BENTO_DB_<n>_*` | every binding |
| `REDIS_HOST`, `REDIS_PORT`, `REDIS_URL` | the app's own Valkey, when it is on |

## Valkey is per app

There is no shared Redis. An app that needs one turns on its own [Valkey](/apps/data#valkey): a Redis-compatible
server inside the app's container, reachable only from that app, with its snapshot kept in the app's home.

## What's durable

App homes, SQLite files, and database volumes. If any of them goes missing, Bento **refuses** to start the app empty
and asks you to restore — it never silently replaces your data with nothing.
