Each card in **Settings** saves on its own. Buttons on cards that need a new container note that **running apps may
restart**; other changes apply without downtime.

## Runtime

Version, routing, document root (PHP) or command, port, and ready path (HTTP process). The runtime *type* can't
change.

## PHP performance settings

Start from **Standard** or **High concurrency**, then override if needed:

| Setting | Default (Standard) | Range |
| --- | --- | --- |
| Max workers | from memory (~6 at 512 MB) | 1–200 |
| Web memory limit | 128 MB | 16–4096 MB |
| Jobs & workers memory limit | 256 MB | 16–8192 MB |
| Max execution time | 60 s | 1–280 s |
| Max input vars | PHP default | 100–100000 |

Your app can still raise web limits with `ini_set()` or a `.user.ini` file in the document root — that's also where
any other PHP setting goes.

## Ingress settings and Hosts

Change the **Access** mode, the app's own access log and its request filters. **Hosts** lists the domains pointing at
this app; manage them in [Ingress](/ingress/hosts). A Public app needs at least one host to publish.

### Request filters

Scanners hit every public site with the same requests: `/.env`, `/wp-login.php`, `/phpmyadmin/`, `backup.zip`. Three
filters answer those with a plain **404 Not Found**. It is a 404 and not a 403 on purpose: a refusal that looks
different from "no such page" tells the scanner the file exists.

| Filter | Default | Blocks |
| --- | --- | --- |
| **Block dot files** | on | Any path with a dot-prefixed part (`.env`, `.git/`, `.htaccess`, `.DS_Store`), except `/.well-known/`. |
| **Block PHP probes** | on | WordPress paths (`wp-admin`, `wp-login.php`, `wp-content`, `xmlrpc.php`…), phpMyAdmin and Adminer, webshell and `phpinfo` file names, PHP source extensions (`.phps`, `.phtml`, `.inc`, `.phar`), and PHP files under `uploads`, `files`, `images`, `media`, `storage`, `cache`, `tmp`, `logs`, `vendor` and similar directories. |
| **Block sensitive files** | on | Backups and leftovers (`.bak`, `.old`, `.orig`, `~`, `.swp`), dumps and logs (`.sql`, `.dump`, `.sqlite`, `.log`), archives (`.zip`, `.tar.gz`, `.7z`…), source maps (`.map`), and package manager files (`composer.json`, `package.json`, lock files, `go.mod`, `requirements.txt`…). |

The filters run in the **edge** for every host that points at this app, and in the app's own Nginx for PHP apps, so
a PHP app is covered even when you reach it without the edge. Apps with external or private ingress get only the app's
own Nginx filters (PHP apps). Hosts that proxy to an external upstream or redirect are not filtered.
Changes apply with an Nginx reload. The app is not restarted.

Turn a filter off when your site really serves what it blocks:

- **WordPress and legacy PHP sites** (routing set to *Legacy*) turn **Block PHP probes** off. They serve `wp-*` paths
  and PHP from many directories by design.
- Turn **Block sensitive files** off if you publish downloads such as `.zip` or `.map` files, or serve
  `package.json` on purpose.

With a filter on, a path it matches is refused even when the file exists. Your own Nginx snippets in
[`routes/`](/ingress/custom-nginx) are read first, so your own regex, exact or `^~` `location` wins for the paths it
matches.

## Container settings

**Memory**, **CPU**, and **Processes** limits, plus the [Valkey and scheduler](#valkey-and-scheduler) switches.

## Environment

Add your own environment variables (API keys, feature flags). Bento's own `DB_*` (and `REDIS_*` when
[Valkey](#valkey-and-scheduler) is on) are provided automatically. Saving restarts a running app.

## Valkey and scheduler

Two services inside the app's container can be turned on or off:

| Setting | Default | Runs |
| --- | --- | --- |
| `valkey` | off | The app's own [Valkey](/apps/data#valkey) on `127.0.0.1:6379` |
| `minicrond` | on | The app's [scheduler](/apps/scheduler): cron jobs and workers |

Toggle **Valkey (Redis alternative)** and **Scheduler (minicrond)** in **Container settings** and save, or pick them in **App
services** when creating the app. From the CLI, use `bento app update <slug> --json patch.json`, e.g.
`{ "valkey": true }`. Changing either replaces a running app's container. Port 6379 is reserved for Valkey, so an HTTP-process
app can't listen on it.

## Permissions

Repairs file ownership in the home — **Check**, **Dry run**, **Shallow repair**, or **Recursive repair**.

## Remove

Type `delete <slug>` to confirm. The container and its domains are removed and its UID retired. The **home and
databases are kept** under **System → Retained data** until you delete them there.
