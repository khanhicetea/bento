The **Data** tab lists the app's **data bindings** — one per database server it uses.

## Add a database

- **Add binding** — pick a data service (e.g. MySQL 8.4, PostgreSQL 17) or **SQLite file**. Bento creates a user for
  the app and a database `<slug>_main`.
- **More databases on the same binding** — type a name (letters and digits) in **New database** and add it. `reports`
  becomes `shop_reports`.

Bindings can't be removed or changed — this protects your data. A running app restarts briefly after a binding is
added, to pick up the new credentials.

<Callout type="note">
Need a database server version that isn't listed? Add it once for the whole stack:
`bento service add --engine postgres --version 17` (PostgreSQL 17 and 18 include pgvector, PostGIS, pg_cron, and
TimescaleDB).
</Callout>

## Use it from your app

Credentials arrive as environment variables — Laravel reads `DB_*` with no `.env` changes:

| Variables | For |
| --- | --- |
| `DB_CONNECTION`, `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` | the first binding |
| `BENTO_DB_<n>_*` | every binding |
| `REDIS_HOST`, `REDIS_PORT`, `REDIS_URL` | the app's own [Valkey](#valkey), when it is on |

SQLite bindings are a private folder at `/var/lib/bento/sqlite/<id>/<slug>.db`, vacuumed weekly.

## Browse data

Each MySQL or PostgreSQL binding has a **Browse** button that opens it in [Adminer](https://www.adminer.org/) in a new
tab, signed in as the app's own user — so you see exactly what the app sees, with full write access.

The browser must be enabled once in **Ingress → Utils → Database browser**. If you reach the UI through an SSH
tunnel, forward port 7781 too:

```bash
ssh -L 7780:127.0.0.1:7780 -L 7781:127.0.0.1:7781 root@your-server
```

Access lasts 30 idle minutes and ends when you sign out. Uploads up to 80 MB, queries up to 15 minutes.

## Valkey

An app can run its own [Valkey](https://valkey.io) (a Redis-compatible server) inside its container, for cache,
sessions, and queues. It is off by default; turn it on with the app's `valkey` setting (see
[Settings](/apps/settings#valkey-and-scheduler)).

- It listens on `127.0.0.1:6379` inside the app's container only, so it has no password and no other app can reach it.
- Bento sets `REDIS_HOST=127.0.0.1`, `REDIS_PORT=6379`, and `REDIS_URL=redis://127.0.0.1:6379`, unless your own
  environment variables already define them — yours win.
- The [Terminal](/apps/terminal)'s tool shell, one-off commands, and deploy commands reach it at the same address while
  the app is running. When the app is stopped, its Valkey is stopped too.
- Its memory counts toward the app's **Memory** limit and is capped at a quarter of it (at least 16 MB). At the
  cap, Valkey evicts the least recently used keys that have an expiry (cache entries, sessions); keys without one
  (queues, locks) are never evicted, and writes fail once only those remain.
- Data is snapshotted to `~/.local/share/valkey/dump.rdb` in the app's home (at most an hour after a single change,
  sooner when busy), so it survives restarts, and [app backups](/backups/app-backups) include it. A restored app
  starts from that snapshot.
