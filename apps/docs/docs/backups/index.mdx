Bento backs up each app with an **app backup**, set up in the app's [Backup tab](/apps/backup): an encrypted,
deduplicated [restic](https://restic.net) snapshot of the app's home **and** a plain dump of every database bound to
it, uploaded to a remote you choose.

| Restore | How |
| --- | --- |
| One database, in place | **Restore DB** on a snapshot — see [Restore a database](/backups/database) |
| The whole app | **Clone** into a new app, on this server or another — see [App backups](/backups/app-backups#restore) |

<Callout type="warning">
A backup that only exists on the same server isn't disaster recovery. Use an off-site remote **and** test a restore.
</Callout>

## Stack backup password

Every repository Bento creates is encrypted with one password per stack, kept at `secrets/restic/stack.key` in the
stack folder (root only). Print it on the host:

```bash
sudo bento --stack /srv/bento/prod backup password
```

<Callout type="danger">
Keep a copy of the stack backup password **off this host**, in a password manager. If it is lost — and every other
key with it — the backups cannot be recovered.
</Callout>

`bento init` creates the password; an older stack gets one when its first repository is created. To use your own,
write it to `secrets/restic/stack.key` (one line, owner root, mode `0400`) **before** the first repository is created.
It travels with [`bento export`](/system/stacks#move-or-clone-a-whole-stack). The API never returns it.

On a stack upgraded from a version before the stack password, repositories created earlier keep their own key: the
stack password does not open them, and `bento backup password` reports none until the next repository is created.
Keep the keys you saved for those repositories, or create a new repository to move an app onto the stack password.

## The Backups screen

The top row shows the **Last backup**, the **Next run**, whether the **Backup password** is **SET** or **NOT YET**,
and how many apps have **No app backup**.

| Tab | Shows |
| --- | --- |
| **App backups** | Every app with app backups: schedule, last result, snapshots, data added, last verification. |
| **Runs** | History of all backup runs, failures highlighted. |
| **Remotes** | Your rclone remotes, **Open shell** to add or edit them, and **Test remote** to check a destination. |
