---
title: Upgrade Bento
description: Replace the binary and restart the service — your apps keep running.
---

```bash
sudo -i
install -m 0755 bento-linux-amd64 /usr/local/bin/bento
systemctl restart bento@prod
bento version
```

Apps, the edge, and databases keep serving during the restart — only management pauses. A running operation is
drained before the service stops.

If a new version changes an app's runtime image or generated configuration, Bento builds the new images while apps keep
serving on the old ones, then replaces running apps one at a time — expect a few seconds of `502` per app. A version
with a new edge image restarts the edge once, which refuses connections for about a second. Check **Activity** after
upgrading.

Databases keep their image until you restart them: a new Bento version can ship a newer patch image of MySQL or
PostgreSQL, and **System → Restart** on that service applies it (it never changes the engine version). The new image
downloads while the database keeps serving; apps lose the database only for the restart itself, a few seconds.

PHP, Debian and toolchain patch releases don't need an upgrade: **System → Images → Rebuild** picks them up, and you
choose when to roll apps onto the new build ([Runtime images](/reference/runtime-images#rebuild-and-roll-out)).

<Callout type="note">
Take a [stack export](/system/stacks#move-or-clone-a-whole-stack) before upgrading. Bento refuses to open state from a
version it doesn't know rather than rewriting it.
</Callout>
