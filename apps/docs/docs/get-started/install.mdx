<Callout type="warning" title="Run everything as root">
Bento manages Docker, owns app home directories, and runs each app under its own Linux user — so it must run as
**root**, and so must every `bento` command. Switch to a root shell before you start:

```bash
sudo -i
```

Running `bento` as a normal user (even one in the `docker` group) fails: the control socket is root-only.
</Callout>

## Before you start

- A Linux server, **amd64** or **arm64**.
- A fresh or dedicated machine is best. Bento will want ports **80** and **443** if you use its built-in edge.
- A domain you can point at the server, if you want public HTTPS.

## Quick install

The bootstrap script does every step below on a fresh server, asks a few questions first, and changes nothing until
you confirm:

```bash
curl -fsSL https://raw.githubusercontent.com/khanhicetea/bento/main/scripts/bootstrap.sh | sudo bash
```

It checks the server (Linux amd64/arm64, systemd, root, memory, disk), then asks:

| Question | Default | Notes |
| --- | --- | --- |
| Alternative HTTP / HTTPS port | — | Asked only when **80** or **443** is already in use. Let's Encrypt needs port 80 to reach the edge. |
| ACME email | — | Your Let's Encrypt contact address. |
| Stack name | `prod` | Also the service name: `bento@prod`. |
| Install the stack in | `/srv/bento/<name>` | Press <kbd>Enter</kbd> for the default. Must be empty or new. |
| MySQL / PostgreSQL version | `8.4` / `none` | Checked against the release being installed. Add more later in the UI. |
| Web UI password | generated | At least 12 characters. A generated one is shown once at the end. |

After a summary and your **y**, it installs `curl` and Docker Engine if missing, downloads the latest release and
verifies its SHA-256, installs `/usr/local/bin/bento` and the `bento@.service` unit, creates the stack, starts
`bento@<name>`, turns on the [edge](/get-started/go-live) with your ports and email, and adds
`export BENTO_STACK_ROOT=...` to root's `~/.bashrc`. A stack outside `/srv/bento` gets its path in
`/etc/bento/<name>.env`.

Then [open the web UI](/get-started/open-the-ui). To install a specific release instead of the latest, pipe into
`sudo BENTO_VERSION=0.3.0 bash`.

<Callout type="note">
The script sets up the first stack on a server. It stops if Bento already listens on `127.0.0.1:7780`; for a second
stack or an upgrade, follow the manual steps or [Upgrade](/system/upgrade). It never changes your firewall — it prints the
`ufw` or `firewalld` command to open the edge ports instead.
</Callout>

## Manual install

<Steps>
  <Step title="Install Docker">
    Bento needs Docker Engine (API 1.44+, i.e. Docker 25 or newer). The quickest way on Debian, Ubuntu, Fedora, and
    friends is Docker's convenience script:

    ```bash
    curl -fsSL https://get.docker.com | sh
    systemctl enable --now docker
    docker version        # check: Server version 25 or newer
    ```

    Already have Docker from your distribution's packages? Fine — just check the version.
  </Step>
  <Step title="Install the Bento binary">
    Download `bento-linux-amd64` (or `bento-linux-arm64` on arm64) from the
    [releases page](https://github.com/khanhicetea/bento/releases), then:

    ```bash
    install -m 0755 bento-linux-amd64 /usr/local/bin/bento
    bento version
    ```
  </Step>
  <Step title="Create a stack">
    A **stack** is one Bento installation with its own folder. Name it `prod` and add a MySQL server:

    ```bash
    bento --stack /srv/bento/prod init --name prod --mysql 8.4
    ```

    Want PostgreSQL instead, or as well? Add `--postgres 17`. You can add more database servers later from the UI.
  </Step>
  <Step title="Start the Bento service">
    The systemd unit ships in the repository at `deploy/systemd/bento@.service`.

    ```bash
    install -m 0644 bento@.service /etc/systemd/system/
    systemctl daemon-reload
    systemctl enable --now bento@prod
    ```

    `bento@prod` serves the stack at `/srv/bento/prod`. It starts after Docker on every boot.
  </Step>
  <Step title="Set your password">
    ```bash
    export BENTO_STACK_ROOT=/srv/bento/prod
    bento auth set-password
    bento status
    ```
    Add the `export` line to root's `~/.bashrc` so you never need `--stack` again.
  </Step>
</Steps>

Next: [open the web UI](/get-started/open-the-ui).

<Callout type="tip">
Stopping or upgrading the Bento service **does not stop your apps**. They are ordinary containers and keep serving;
only management pauses.
</Callout>
