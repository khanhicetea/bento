---
title: Stack layout
description: Every file and directory in a stack root, and which ones are durable.
---

```text
/srv/bento/prod/
├── bento.db                 intent, identities, UID ledger, operations, sessions (0600)
├── homes/<slug>/            app homes — DURABLE; code in homes/<slug>/app/
├── sqlite/<id>/             SQLite binding directories — DURABLE
├── apps/<appId>/config/     generated config + credentials, mounted read-only at /etc/bento
├── apps/<appId>/identity/   generated passwd/group
├── services/<name>/         data-service secrets (0400)
├── edge/
│   ├── conf/{live,previous} edge Nginx generations
│   ├── custom/              your drop-ins
│   ├── certs/               certificates
│   └── acme/                ACME state
├── cloudflared/token        tunnel token (0440)
├── state-backups/           copies of bento.db taken before each schema upgrade (0600; not exported)
├── secrets/restic/stack.key     stack backup password (root, 0400) — keep a copy off the host
├── secrets/restic/<appId>.key   per-app repository keys (0400), kept after removal
├── rclone/rclone.conf       rclone remotes (yours; must not be encrypted)
└── run/ locks/ cache/ staging/   runtime coordination, not durable
```

MySQL and PostgreSQL data live in Docker volumes named `bento-<stack>-<service>-data`. An app's own Valkey keeps its
snapshot in its home, at `homes/<slug>/.local/share/valkey/dump.rdb`.

## Notes

- `bento.db` carries a schema version. A newer Bento upgrades an older supported schema in place when it starts,
  after copying the database to `state-backups/`; a failed upgrade leaves `bento.db` unchanged. A database from an
  unknown, newer, or too old version is refused and left untouched.
- A `backups/` folder of database dumps from an older Bento is left as it is: Bento no longer writes to it, never
  deletes it, and `bento export` skips it.
- An app restored from an app backup keeps the source's path inside the container (e.g. `/home/shop`); the host
  directory is still `homes/<new-slug>/`.
