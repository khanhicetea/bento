## Stack backup password

```bash
sudo bento --stack /srv/bento/prod backup password
```

Prints the password every repository this stack created is encrypted with. It reads
`secrets/restic/stack.key` on the host (root only) — the API never returns it. Keep a copy **off the host**: if it is
lost, the backups cannot be recovered. See [Stack backup password](/backups#stack-backup-password).

## Restore one database

```bash
bento app restore-db shop --database shop                    # newest snapshot
bento app restore-db shop --database shop --snapshot 1a2b3c4d
bento app restore-db shop --database shop_main --binding b1a2  # a name in two bindings (MySQL and PostgreSQL)
```

Replaces one database of the app with its dump in an app backup snapshot. `--database` is a MySQL or PostgreSQL
database name, or a SQLite file id. Asks you to type `replace <database>`. See
[Restore a database](/backups/database).

## Restore an app backup from another stack

```bash
bento app restore-from-backup --repo s3:bucket/shop --key-file ./shop.key --slug shop-staging
```

Without `--key-file`, this stack's backup password is used.

| Option | Effect |
| --- | --- |
| `--backup-after same-repo` | keep backing up to that repository with that key (schedule off) |
| `--backup-after new-repo` | prepare a separate repository; don't keep the key |
| `--keep-username` | reuse the source database user when free |

App backup setup itself is done in the app's [Backup tab](/apps/backup).
