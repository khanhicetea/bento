# Bento enhancement work: what to do first

Status: prioritized work proposal, not an approved change to the current product contract. Based on `bento-questions.md`, the current code, and `specs/01-product-spec.md`, `02-system-architecture.md`, `03-reimplementation-contract.md`, `04-proposed-product-enhancements.md`, `05-proposed-technical-improvements.md`, and `06-minicrond-migration-plan.md`.

## Decision

**Make stack transfer SQLite-consistent first (T-04).** Export currently archives a live `sqlite/` tree without quiescing writers. A successful transfer can therefore contain inconsistent database bytes.

**First deliverable:** define a versioned SQLite-aware snapshot component for transfer and verify it with concurrent WAL writers. Keep live filesystem copies separate from recovery-grade logical artifacts.

## Interface and architecture guardrails

- Invest in **CLI + web**, using the same domain operations and contracts. Preserve CLI recovery without the browser and useful existing prompts, but do not expand a third full TUI. Maintain narrow cache/query boundaries in web features.
- Keep the web control plane loopback-safe; its scheduler gateway already has conditional Basic-auth/session protection, which is **not** blanket authorization for every web feature or a reason to expose the server to an untrusted network. Require a separate security design before remote access.
- Keep Docker Compose and Nginx for this single-host product. Investigate Go, Caddy, Podman/Quadlet, or a second orchestrator only after a measured problem and an isolated acceptance-test prototype; do not change language, ingress, and runtime topology in one release.
- Do not weaken exact destructive confirmations, remove durable data during cleanup, run `compose down -v`, expose secrets, write runtime data into the checkout, or edit generated stack output. Every shipped behavior change needs baseline spec/docs updates, source/compiled parity, applicable Docker integration, and explicit recovery/rollback notes.

## Suggested first PR boundary

Start with a lock-design PR, followed by the versioned SQLite transfer format. Keep each risky change reviewable and reversible. This keeps each risky change reviewable and reversible.
