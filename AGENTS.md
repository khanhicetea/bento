# AGENTS.md

These rules apply to the whole repository. A more specific `AGENTS.md` in a subdirectory overrides them for that subtree.

## Project fundamentals

- Bento is a single-host control plane: a resident Go backend (`apps/backend`) that manages Docker Engine directly,
  keeps desired state in SQLite, serves a REST API and the React UI, and a thin Go CLI that talks to it.
- Architecture, contributor recipes, and verification records live in `apps/backend/docs/`. Operator documentation
  lives in `docs/`.
- Go 1.27 for the backend. The frontend and docs site use their locked JavaScript toolchain (see `mise.toml` and the
  root `package.json`). Keep dependency versions exact and commit `go.mod`, `go.sum`, and lockfile changes.
- Stack roots are external mutable operator state. Never write runtime state beside the source tree or binary.

## Repository boundaries

- `apps/backend`: Go module. `cmd/bento` (serve, init, import, client commands); `internal/api` (REST, auth,
  streams, scheduler gateway) with the wire contract in `internal/api/dto`; `internal/operations` (all runtime
  mutations as durable operations); `internal/reconcile`; `internal/store` (SQLite); `internal/docker` (the only
  package that imports the Docker SDK); `internal/runtime` (names, labels, container specs, generated app config);
  `internal/edge`, `internal/dataservices`, `internal/backup`, `internal/transfer`, `internal/scheduler`,
  `internal/platform`.
- `apps/backend/templates`: immutable runtime image contexts and config templates embedded in the binary.
- `apps/web`: React 19 control plane. `src/api/generated/types.ts` is generated by tygo — never edit or reformat it.

## Backend

Backend work follows [`apps/backend/AGENTS.md`](apps/backend/AGENTS.md): handlers only persist intent and submit
operations, effects happen in operation handlers, ownership is verified before destructive actions, durable data is
never recreated empty, and secrets never reach argv, labels, logs, or API responses. After changing
`apps/backend/internal/api/dto`, run `make -C apps/backend generate-types` and commit the output.

## React 19 and server state

- Function components and React 19 APIs. Do not add `useMemo`, `useCallback`, or `React.memo`.
- `useState` only for local, ephemeral UI state. Remote state goes through `@tanstack/react-query`; never mirror it in
  component state or fetch it with `useEffect`.
- Use the typed transport in `apps/web/src/api/client.ts` and key factories in `apps/web/src/api/keys.ts`. Accepted
  operations are tracked with `useTrackOperation`; invalidate the narrowest affected keys.
- Keep one `QueryClientProvider` at the entry point.

## Safety and compatibility

- Never weaken exact confirmations (`delete <slug>`, `delete`, `replace <db>`, `export`, `delete <proxy>`).
- Unsupported or unknown state is refused, never rewritten or re-initialized.
- The management listener is loopback-only; do not imply the UI is safe on an untrusted network.
- Preserve the add-only binding model, UID non-reuse, and retained-data semantics on removal.

## Tests and required checks

```bash
bun run fmt:check && bun run lint && bun run check && bun run web:build
make -C apps/backend ci                 # gofmt, vet, race tests, generated-type drift, build (run as root)
make -C apps/backend test-integration   # real Docker; disposable roots only
```

Do not claim Docker-dependent, arm64, tunnel, or ACME checks passed if they were skipped. Report changed files,
checks run, and remaining risk.
