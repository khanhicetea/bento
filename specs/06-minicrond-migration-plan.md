# Proposed plan: replace Supercronic and delegate app jobs to minicrond

Status: implementation plan; the minicrond 0.2 runtime migration and authenticated local browser gateway are implemented. Remote exposure remains unsupported until trusted TLS ingress/origin configuration exists. Companion: `../../minicrond/docs/bento-integration-plan.md`. **Decision:** Bento is pre-production; do not migrate its old cron/worker rows or preserve Supercronic compatibility. Remove Supercronic entirely. Minicrond remains an independent Linux scheduler/supervisor, not a Bento-owned registry.

## Ownership and topology

- Keep s6-overlay PID 1 and one PHP runner per version. Start **one minicrond process per enabled PHP app**, under that app's UID/GID, whether or not it has user jobs yet. It owns that app's jobs, workers, run history, logs, definitions, and local socket in a private writable directory under the external stack root (for example `homes/<slug>/.local/share/minicron`). One app cannot read or control another app's instance. No per-app TCP listener or published Docker port. The app user may edit definitions through minicrond CLI, API, or web UI without a Bento render/apply cycle.
- Keep a distinct root-run minicrond process per runner for root-only logrotate. **Only Bento-internal tasks** may be provisioned by Bento: deploy queue drain, each managed SQLite VACUUM, and root logrotate. These are not user jobs, must have reserved documented names, and must be rendered as config-owned `[[job]]` entries in each daemon's main config. Minicrond 0.2.2 syncs these before scheduling or accepting requests and rejects name collisions with registry-owned definitions; never overwrite user-owned definitions. App users can still control their daemon and files under their UID; this is not a privilege boundary. Decide whether a critical internal task instead needs a separate privileged service, without moving user jobs back into Bento.
- Minicrond supervises app workers, not Bento/s6. s6 supervises the minicrond daemon and any deliberately separate Bento-internal helpers. A minicrond crash restarts only that app's daemon. Runner scaling beyond one replica remains unsupported (duplicate firings).
- Bento has no application job/worker desired-state copy. Delete `cronJobs[]` and `workers[]` from its state model, schemas and relational tables (new development schema; no legacy migration), add/edit/remove CLI commands, web forms, oRPC CRUD/log endpoints and generated crontabs/scripts/worker services. Replace Bento Jobs/Applications views with an app-scoped **Open scheduler** link and optional daemon health/version; never mirror minicrond's registry in Bento state. Leave host crontab for host backup/maintenance operations alone unless separately redesigned.

## App operator CLI

Provide a thin `bento app minicrond <slug> -- <minicrond args...>` context command that resolves the enabled app and runner from Bento state, validates the slug, and invokes the shipped minicrond binary inside the runner as that **numeric app UID/GID** with explicit `MINICRON_DATA`, `HOME`, `USER`, `PATH`, and `TZ`. Pass argv as argv, never via a shell or logs. Return the exit code/stdout/stderr safely; bound output and redact errors as appropriate. Do not reinterpret `import`, `run`, `logs`, or `service` commands as Bento state mutations. Document direct `docker compose exec --user UID:GID ... minicrond ...` for operators with Docker access; the private Unix socket and peer UID enforce per-app control. Check how minicrond CLI discovers an identity with no passwd entry; either create a correct app passwd entry in the image/runtime or use the companion plan's generic numeric-UID fix. Do not give app users root, Docker socket access, another app's directory, or the maintenance daemon's socket.

## Embedded web UI: authenticated proxy, not token handoff

A pre-authenticated iframe must be a **Bento proxy to the app's own minicrond UI and API**, not a minicrond bearer token in a URL, HTML, `postMessage`, JavaScript storage, or browser responses. Minicrond's transport-aware UI can omit its browser token over the authenticated Unix transport. With minicrond's `BASE_PATH` support, Bento serves each app at `/scheduler/apps/<slug>/` on the Bento origin, backed by an expiring host-only HttpOnly session created only after configured Basic authentication. This intentionally sacrifices browser-origin isolation: untrusted scheduler content or XSS in one scheduler can access Bento and other schedulers under that origin. Do not treat app paths as a security boundary; this mode is for trusted operators and trusted scheduler content only. A raw iframe URL still does **not** meet this requirement.

1. First add mandatory Bento authentication/session for this feature; if disabled, show no iframe and do not enable its proxy. Loopback-only is not authentication. Require explicit per-app authorization for **every** asset, API, SSE, download, and navigation request; do not assume a successful iframe launch authorizes later requests. Limit local deployment to loopback; remote use requires an explicitly trusted TLS/authenticated ingress. Protect writes with exact Origin/Fetch Metadata/CSRF checks, session expiration, no CORS to arbitrary origins, no cache of user data, and request/body/stream limits. Do not trust forwarded host/proto headers except from a configured proxy.
2. Configure each app's minicrond `BASE_PATH=/scheduler/apps/<slug>/` and forward the full prefixed path to that app's socket. Only these exact path segments may route to the proxy. Assets, navigation, API, SSE and downloads must stay under the prefix. Bento's `frame-src` permits self and the proxied UI replaces minicrond's `X-Frame-Options: DENY` only on proxy responses. This explicitly accepted same-origin mode has no XSS isolation between apps or Bento; keep the standalone UI unchanged.
3. Bento's authenticated proxy must talk to **only the selected app's** private minicrond Unix socket, with no host-exposed or cross-app fallback. Minicrond currently requires the socket caller's UID to match the app UID; implement a minimal Bento-owned, UID-matched per-app local socket relay if necessary, rather than weakening minicrond's peer-auth or mounting all app sockets into the web service. The relay exposes only the selected daemon to the privileged Bento proxy, never directly to browsers; validate socket ownership/paths, restrict filesystem permissions, strip hop-by-hop/client auth headers, stream SSE/downloads, and handle failure without leaking credentials. No Compose shell command per HTTP request. Verify the proxy does not let the embedded UI rotate a credential needed for proxy access; prefer minicrond's peer-auth with no token at all.
4. Minicrond's independently useful UI improvement (companion plan): when its API is already accessible over an authenticated Unix transport, allow the SPA to detect that and skip its bearer-token login; retain the normal token login for standalone TCP. The Bento proxy supplies authentication on every request; the browser does not acquire minicrond credentials. Keep a non-iframe **Open scheduler** option for accessibility/debugging on the protected app path. Test missing auth, wrong app, forged Origin, CSRF, path traversal, session expiration, SSE, downloads and frame/CSP policy. Same-origin XSS isolation is not provided.

## Implementation sequence

1. Land the small, general minicrond prerequisites and release pinned, checksum-verified linux/amd64 and linux/arm64 binaries. In `apps/cli/templates/docker/php/Dockerfile`, remove Supercronic download/arguments and install minicrond by immutable digest. Update immutable templates and source/compiled parity checks. Keep PHP, Composer and Node in the app command PATH.
2. Change Bento's development state schema and UI/API/CLI to delegate user jobs/workers entirely; delete Supercronic strings, render/reload signaling, generated crontabs, Bento-managed worker services, fixtures and obsolete documentation. Provision private per-app minicrond dirs and app-UID s6 run scripts. Keep runtime writes in the operator stack root, not beside source or compiled binary.
3. Render the few Bento-internal tasks into minicrond 0.2.2's main config as config-owned `[[job]]` entries, separate from registry-owned user definitions. The daemon atomically syncs them before scheduling/listening; invalid config or a registry name collision fails startup rather than running stale work. A changed config triggers a scoped s6 restart. Removed config-owned entries are disabled by minicrond. Previously imported Bento-internal registry definitions must be removed using the old daemon before upgrading; 0.2.2 deliberately refuses to take over their names. Do not automatically delete registry-owned definitions during startup.
4. Build and security-test the Bento per-app authenticated proxy and iframe UI. The proxy must be independently disabled if Bento auth or safe origin isolation is unavailable. The existing optional Basic auth must not be treated as a complete delegated session model. Document the local/remote origin setup, CLI access, permission model, disk/retention and stack backup/transfer of minicrond's SQLite DBs/WAL/log buffers (live `stack.tar.gz` is not a consistent SQLite snapshot).
5. Update baseline `specs/`, README, guides, help, supply-chain inventory and tests with implementation. Because this is pre-production, **no** dual-scheduler cutover, old-row migration, legacy crontab compatibility or rollback-to-Supercronic path is required. Do not keep Supercronic in final code/docs except a short historical note if useful.

## Acceptance gates

- Unit/contract: no Bento state or API for user jobs/workers; app and root daemon generation is deterministic; app identity/directory/socket permissions; reserved internal names cannot clobber user jobs; deploy drain/VACUUM/logrotate tasks remain scheduled; no Supercronic asset or reload path remains.
- Docker integration: two apps have independent CLI/UI, definitions, worker supervision, logs, sockets and failures; app user cannot control sibling/root daemon; job/worker edits through minicrond persist across Bento render and runner restart; config-owned task sync fails closed on collisions and does not remove user definitions; disabling app stops its daemon without disturbing siblings; cron fires once; deploy, SQLite maintenance and logrotate still work.
- Web security: tests on real HTTP + socket bridge for all proxy routes and streaming, iframe without token or login, required Bento auth, app authorization, same-origin/CSRF, frame policy, prefix routing, no token in URLs/responses/logs, and access denied after logout/session expiry. Test missing/dead daemon and degraded operation. Run Bun formatting/lint/check/test, relevant Docker integration, web check/build and compiled parity checks; report unavailable checks honestly.
